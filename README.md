# Hamshmareh Desktop Agent و ربات استخراج شماره

این پروژه هستهٔ استخراج شماره‌های قابل‌مشاهده در بخش «انتخاب شماره» محصولات سیم‌کارت را داخل یک برنامهٔ دسکتاپ ویندوزی در اختیار Hamshmareh قرار می‌دهد. Website فقط Control Plane است؛ استخراج و درخواست به API ایرانسل روی رایانهٔ کارفرما اجرا می‌شود.

ربات از endpoint عمومی فروشگاه استفاده می‌کند؛ وارد حساب نمی‌شود، OTP نمی‌خواهد، خرید انجام نمی‌دهد و چیزی به سبد اضافه نمی‌کند. درخواست‌ها تک‌به‌تک و با فاصله ارسال می‌شوند و پاسخ‌های 429 با backoff مدیریت می‌شوند.

## اجرای Desktop Agent

برای استفادهٔ عادی کارفرما، فایل `HamshmarehExtractor.exe` را اجرا کنید. برنامه GUI مستقل دارد و به Python، Terminal، CMD یا نصب دستی dependency نیاز ندارد.

در اولین اجرا:

1. آدرس Backend را در Settings وارد کنید؛ مقدار پیش‌فرض برای توسعه `http://localhost:5050/api` است.
2. کد یک‌بارمصرفی را که مدیر از پنل سایت ساخته است وارد کنید.
3. اتصال را برقرار کنید، پروژه را انتخاب کنید و Job صف‌شده را اجرا کنید.

توکن روی Windows با DPAPI در `%LOCALAPPDATA%\HamshmarehExtractor` نگهداری می‌شود. برنامه فقط یک Instance را قبول می‌کند و لاگ چرخشی آن در `logs/app.log` همان مسیر قرار دارد.

## چرا استخراج با الگوی `*` انجام می‌شود؟

رابط سایت در هر بار پاسخ فقط یک بلوک محدود از شماره‌ها را می‌گیرد و دکمهٔ «صفحه بعد» می‌تواند همان بلوک را دوباره برگرداند. ربات وقتی یک الگو به سقف پاسخ می‌رسد، اولین `*` را به رقم‌های ۰ تا ۹ تقسیم می‌کند و همین کار را تا رسیدن به الگوهای کوچک ادامه می‌دهد. شماره‌ها با کلید یکتا در SQLite ذخیره می‌شوند؛ بنابراین هم تکراری حذف می‌شود و هم اجرای قطع‌شده قابل ادامه است.

## اجرای هسته برای توسعه

برای یک تست محدود:

```powershell
python .\irancell_number_bot.py --products 565 --max-requests 2 --delay 1.5
```

برای اجرای کامل هر ۱۵ محصول در حالت مستقل توسعه:

```powershell
python .\irancell_number_bot.py --products all --delay 8 --retry-forever-429 --rate-limit-cooldown 600
```

اگر اجرا قطع شود، همان دستور را دوباره اجرا کنید؛ از `state.sqlite3` ادامه می‌دهد و از ابتدا شماره‌های انجام‌شده را تکرار نمی‌کند. برای بازسازی خروجی‌های CSV/TXT:

```powershell
python .\irancell_number_bot.py --products all --export-only
```

Desktop Agent نیز هنگام اجرای سورس، state موجود در `output` پروژه را شناسایی و از همان‌جا ادامه می‌دهد؛ بنابراین با تغییر نسخه، شماره‌ها و الگوهای قبلی دوباره از ابتدا شروع نمی‌شوند. در صورت نیاز می‌توان مسیر محلی دیگری را با متغیر محیطی `HAMSHMAREH_OUTPUT_DIR` تعیین کرد. این مسیر باید محلی و قابل‌اعتماد باشد.

## خروجی و پایداری

برای هر محصول یک پوشهٔ جدا در `output` ساخته می‌شود:

- `numbers.txt`: هر شمارهٔ نرمال‌شده در یک خط
- `numbers.csv`: شماره، قالب نمایشی، پیش‌شماره، الگوی کشف و مقدار خام سایت
- `metadata.json`: اطلاعات محصول و پیش‌شماره‌ها
- `summary.json`: وضعیت و تعداد شماره‌های یکتا
- `state.sqlite3`: صف الگوها و دادهٔ قابل‌ادامه
- `numbers.partial.txt`: خروجی افزایشی حین اجرا

Desktop Agent علاوه بر state ربات، شماره‌های پیدا‌شده و batchهای ارسال‌نشده را در SQLite محلی نگه می‌دارد. هر ۵۰ شماره یا بر اساس زمان تنظیم‌شده به Backend ارسال می‌شوند. پس از قطع شبکه، بستن پنجره، crash یا Windows restart، checkpoint استخراج و صف Sync ادامه پیدا می‌کند و Backend با `batchId` idempotent و unique constraint از duplicate جلوگیری می‌کند.

هستهٔ ربات event/callbackهای شروع، محصول، شمارهٔ جدید، progress، rate limit، خطا و پایان را منتشر می‌کند. GUI و Sync Service از همین مرز استفاده می‌کنند و منطق delay، retry، `Retry-After`، backoff، resume و تفکیک محصول حفظ شده است.

## Desktop GUI و داشبورد قدیمی

GUI وضعیت اتصال، دستگاه، حساب، پروژه، محصول، تعداد استخراج‌شده، تعداد Sync‌شده، صف محلی، زمان آخرین Sync، وضعیت Job و خطاهای اخیر را نمایش می‌دهد و دکمه‌های اتصال، شروع، Pause، Resume، Stop، Retry Sync و Settings را دارد.

Dashboard قدیمی روی `127.0.0.1:8765` فقط ابزار توسعه/اشکال‌زدایی است و برای استفادهٔ عادی کارفرما لازم نیست. برای اجرای عمدی آن:

```bat
dashboard.bat
```

برای اجرای عمدی CLI قدیمی بدون GUI از `legacy_extraction.bat` استفاده کنید؛ مسیر عادی `start_extraction.bat` ابتدا EXE دسکتاپ را اجرا می‌کند و در صورت نبودن build به نسخهٔ Python GUI برمی‌گردد.

محصول ۱۲۶ (سیم‌کارت TD-LTE) در API فروشگاه addon انتخاب شماره ندارد؛ بنابراین با وضعیت `skipped_no_number_selection` ثبت می‌شود.

## Build EXE

با Python 3.12 و dependencyهای build:

```powershell
python -m pip install -r .\requirements-build.txt
.\build_exe.ps1
```

خروجی قابل تحویل:

```text
dist\HamshmarehExtractor.exe
```

تست راه‌اندازی اولیهٔ executable:

```powershell
.\dist\HamshmarehExtractor.exe --smoke-test
```

## تنظیمات و API

آدرس Backend در source code ثابت نیست و از تنظیمات محلی یا متغیر محیطی `HAMSHMAREH_API_BASE_URL` خوانده می‌شود. برای آدرس غیرمحلی، برنامه فقط HTTPS را قبول می‌کند. Endpointهای Pairing، status، projects، jobs، heartbeat، progress، batch و completion در `desktop_agent/api_client.py` پیاده‌سازی شده‌اند.

## تست محلی

```powershell
python -m unittest discover -s . -p "test*.py"
```

اجرای کامل ممکن است بسته به تعداد شماره‌ها و محدودیت سرویس طولانی باشد. فقط یک نمونه از ربات را هم‌زمان اجرا کنید و فاصلهٔ درخواست‌ها را کم نکنید.

اگر API کد 429 برگرداند، حالت `--retry-forever-429` ربات را متوقف نمی‌کند؛ حداقل ۱۰ دقیقه صبر می‌کند و از همان state ادامه می‌دهد. این گزینه برای دورزدن محدودیت نیست و فقط از ارسال درخواست‌های بیشتر هنگام rate-limit جلوگیری می‌کند.

## انتشار عمومی

داده‌های runtime، state دیتابیس و فایل‌های شمارهٔ تلفن عمداً در مخزن عمومی commit نمی‌شوند و در `.gitignore` قرار دارند. این مخزن شامل هستهٔ ربات، Desktop Agent، GUI، داشبورد legacy، تست‌ها و مستندات است؛ خروجی شماره‌ها، توکن، SQLite runtime و logها فقط در مسیرهای محلی باقی می‌مانند.
