# ربات استخراج شماره‌های فروشگاه ایرانسل

این پروژه شماره‌های قابل‌مشاهده در بخش «انتخاب شماره» محصولات سیم‌کارت را برای هر محصول جداگانه استخراج می‌کند.

ربات از endpoint عمومی فروشگاه استفاده می‌کند؛ وارد حساب نمی‌شود، OTP نمی‌خواهد، خرید انجام نمی‌دهد و چیزی به سبد اضافه نمی‌کند. برای رعایت فشار روی سرویس، درخواست‌ها تک‌به‌تک و با فاصله ارسال می‌شوند و پاسخ‌های 429 با backoff مدیریت می‌شوند.

## چرا استخراج با الگوی `*` انجام می‌شود؟

رابط سایت در هر بار پاسخ فقط یک بلوک محدود از شماره‌ها را می‌گیرد و دکمهٔ «صفحه بعد» در آزمایش فعلی می‌تواند همان بلوک را دوباره برگرداند. ربات به‌جای تکرار بی‌نهایت آن صفحه، وقتی یک الگو به سقف پاسخ می‌رسد، اولین `*` را به رقم‌های ۰ تا ۹ تقسیم می‌کند و همین کار را تا رسیدن به الگوهای کوچک ادامه می‌دهد. شماره‌ها با کلید یکتا در SQLite ذخیره می‌شوند؛ بنابراین هم تکراری حذف می‌شود و هم اجرای قطع‌شده قابل ادامه است.

## اجرا

برای یک تست محدود:

```powershell
python .\irancell_number_bot.py --products 565 --max-requests 2 --delay 1.5
```

برای اجرای کامل هر ۱۵ محصول:

```powershell
python .\irancell_number_bot.py --products all --delay 8 --retry-forever-429 --rate-limit-cooldown 600
```

اگر اجرا قطع شود، همان دستور را دوباره اجرا کنید؛ از `state.sqlite3` ادامه می‌دهد و از ابتدا شماره‌های انجام‌شده را تکرار نمی‌کند. برای بازسازی خروجی‌های CSV/TXT از دادهٔ ذخیره‌شده:

```powershell
python .\irancell_number_bot.py --products all --export-only
```

## خروجی

برای هر محصول یک پوشهٔ جدا در `output` ساخته می‌شود:

- `numbers.txt`: هر شمارهٔ نرمال‌شده در یک خط
- `numbers.csv`: شماره، قالب نمایشی، پیش‌شماره، الگوی کشف و مقدار خام سایت
- `metadata.json`: اطلاعات محصول و پیش‌شماره‌ها
- `summary.json`: وضعیت و تعداد شماره‌های یکتا
- `state.sqlite3`: صف الگوها و دادهٔ قابل‌ادامه
- `numbers.partial.txt`: خروجی افزایشی حین اجرا

## داشبورد وضعیت برای کارفرما

برای اجرای هم‌زمان ربات و داشبورد با یک فایل، این فایل را اجرا کنید:

```bat
start_extraction.bat
```

این لانچر اگر ربات از قبل فعال باشد اجرای دوم ایجاد نمی‌کند و ربات از state
ذخیره‌شده ادامه می‌دهد.

اگر فقط داشبورد را می‌خواهید و ربات از قبل در حال اجراست:

برای دیدن تعداد شماره‌ها، محصول فعال، الگوی در حال بررسی، صف باقی‌مانده، وضعیت
ربات، خطاهای اخیر و فایل‌های خروجی، فایل زیر را اجرا کنید:

```bat
dashboard.bat
```

داشبورد فقط روی همین رایانه و آدرس `127.0.0.1:8765` باز می‌شود و فقط state و
لاگ‌های محلی را می‌خواند. برای اجرای مستقیم از CMD نیز می‌توان زد:

```bat
python .\dashboard.py --output .\output --open-browser
```

محصول ۱۲۶ (سیم‌کارت TD-LTE) در API فروشگاه addon انتخاب شماره ندارد؛ بنابراین پوشهٔ آن با وضعیت `skipped_no_number_selection` ثبت می‌شود.

## تست محلی

```powershell
python -m unittest .\test_irancell_number_bot.py
```

اجرای کامل ممکن است بسته به تعداد شماره‌ها و محدودیت سرویس، طولانی باشد. فقط یک نمونه از ربات را هم‌زمان اجرا کنید و فاصلهٔ درخواست‌ها را کم نکنید.

اگر API کد 429 برگرداند، حالت `--retry-forever-429` ربات را متوقف نمی‌کند؛ حداقل ۱۰ دقیقه صبر می‌کند و از همان state ادامه می‌دهد. این گزینه برای دورزدن محدودیت نیست و فقط از ارسال درخواست‌های بیشتر هنگام rate-limit جلوگیری می‌کند.

## انتشار عمومی

داده‌های runtime، state دیتابیس و فایل‌های شمارهٔ تلفن عمداً در مخزن عمومی
commit نمی‌شوند و در `.gitignore` قرار دارند. این مخزن شامل کد ربات، داشبورد و
مستندات است؛ خروجی شماره‌ها فقط در مسیر محلی `output/` باقی می‌ماند.
